原 Silicon Data Token/GPU/RAM 指数不作为自动接入方案：Basic 可免费浏览有限历史，但官方将 API 放在付费计划，并说明再分发指数需要另行许可。免费网页可见不等于免费数据接口。[价格与授权说明](https://www.silicondata.com/pricing)。

七麦的月榜、季度分值本轮未发现适合此项目的稳定免费官方接口。因此建议替换，并保留“口径变化”说明，历史系列分开，不拼接成同一指标。

OpenRouter 使用量注意事项：每日 Top 50 + other 可恢复平台每日总量，但将日榜按模型求和不一定恢复完整周模型榜，因为某模型未进日榜时数据会归入 other。实现应优先验证 period=week 的官方输出；使用 UTC 统计区间并在中文界面说明。保存原始大整数为字符串或 Python int，避免 JavaScript 浮点误差。不同提供商的 tokenizer 不同，Token 数量是粗略工作量指标，不等于用户数、付费金额或能力水平。[官方接口](https://openrouter.ai/docs/api/api-reference/datasets/daily-token-totals-for-top-50-models)、[Data API 使用与许可](https://openrouter.ai/docs/cookbook/administration/data-api)。

Token 报价注意事项：prompt/completion 是每 Token 美元报价，展示每百万 Token 需乘 1,000,000；免费模型独立展示；负数/动态价格不进入固定报价均值；输入、输出、缓存及分档价格不能混合。自建趋势需固定样本和方法，不能标为 Silicon Data 指数。[模型接口](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)、[本轮可读取的公共 JSON](https://openrouter.ai/api/v1/models)。

GPU 报价注意事项：统一币种、区域、型号、GPU 数量、On-demand/Spot、实例包含的 CPU/RAM；云虚拟机整机价格除以 GPU 数量只是实例成本分摊，不等于单独 GPU 租金。读取报价不会租用 GPU。[Azure API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices/azure-retail-prices)、[Runpod 报价](https://www.runpod.io/pricing)。

Apple 注意事项：免费榜是应用免费下载安装的榜单名称，不意味着应用内服务免费；AI 标签来自维护的应用清单，不将所有办公/网盘应用自动当成纯 AI 产品。[官方 RSS Builder](https://rss.marketingtools.apple.com/)、[中国区 JSON](https://rss.marketingtools.apple.com/api/v2/cn/apps/top-free/100/apps.json)。

其他来源：[HF Hub API](https://huggingface.co/docs/hub/en/api)、[36氪 RSS 订阅中心](https://www.36kr.com/rss-center)、[DRAMeXchange 当前报价](https://www.dramexchange.com/)、[DRAMeXchange 条款](https://www.dramexchange.com/About/TermsOfUse)。

## 5. 建议架构：保留 GitHub，补齐持久存储与模块接口

数据源 → 独立采集适配器 → 校验与标准化 → 持久历史快照 → 指标计算 → 版本化 JSON → GitHub Pages 中文 HTML。

GitHub Actions 负责按时启动程序，不是数据源，也不是持久数据库。建议第一版沿用 Releases 的压缩快照；新闻按日归档，指标按日存档，前端只发布最近数据及精简趋势。必要时在计算过程中使用 SQLite，但 runner 内文件必须保存至持久存储并在下一次恢复，不能假定跨运行存在。是否第一版就引入 SQLite，待用户确认。

JSON 统一包含 dataset、schema_version、source、source_url、observed_at、collected_at、generated_at、period、unit、methodology、status、rows。存储访问由统一接口承担，前端不感知底层是 Releases、文件还是数据库。以后增加在线数据库时可保持前端数据契约。

采集调度建议：新闻每小时一次，指标每天一次，季度原始资料每天检查但只在新报告出现时更新。不在新闻任务里重跑 HF。采集完成后恢复其他模块最近成功文件，再原子发布完整站点，避免单模块更新覆盖其他栏目。无变化时跳过重新部署，避免无谓资源消耗。

前端打开时 fetch 最新 JSON，刷新按钮也只读取最新已发布结果。显示数据日期、最后成功时间和过期状态，不承诺第三方尚未公布的日期会有新数值。

需要数据库 API 或私密访问时，再评估 Cloudflare Workers + D1 Free；本轮不创建新账户或服务。[D1 Free 超限会拒绝请求](https://developers.cloudflare.com/d1/platform/pricing/)。对现阶段需求，它增加账户与运维复杂度，尚无必要。

## 6. 零成本与运行边界

- 保持现有公开仓库、免费 github.io 地址、标准 GitHub-hosted Linux runner；不启用大型 runner、付费数据包、域名或付费 LLM 推理。[Actions 免费范围](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。
- 设置快照压缩、历史保留、Actions artifacts 短保留和预算控制，免费计算不等于无限存储。
- hourly 是目标调度频率，GitHub schedule 可能延迟/丢弃，公开仓库长期无活动可能停用计划任务。必须显示失败与过期状态，而非保证每小时精确更新。[官方调度说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。
- 公共 HTML 与数据仍可被他人访问。“个人使用”不自动意味着“只有本人可访问”。需要确认是否要求私密访问。[Pages 概述](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。
- 中文新闻优先接入中文原始来源，国际来源保留原文与中文术语解释。全自动英文长文翻译若需要模型，应作为独立可选模块，只有确认永久免费且无付费 fallback 后再接入。
- RAM 原口径与 OpenRouter 密钥接口目前仍有明确接入缺口，不能宣称九类原始数据已全部通过零成本自动化验证。
